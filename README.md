# NixOS Configuration

[![check](https://github.com/harveywuk/NixOS-BTW/actions/workflows/check.yml/badge.svg)](https://github.com/harveywuk/NixOS-BTW/actions/workflows/check.yml)

![Desktop](./screenshots/desktop.png)

My NixOS configuration using the [den](https://github.com/denful/den) framework with [flake-parts](https://flake.parts/) and [import-tree](https://github.com/vic/import-tree).

Originally based on [neonvoidx/nix](https://github.com/neonvoidx/nix) — see [Credits](#credits).

## Structure

```
├── flake.nix              # Auto-generated by flake-file — do not edit directly
├── flake.lock             # Lock file — updated via `nix flake update`
├── .sops.yaml             # SOPS age encryption configuration
├── treefmt.toml           # Formatter config (nixfmt), exposed as `nix fmt`
├── .github/workflows/     # CI — see Checks
├── hosts/                 # Hardware-generated configs (nixos-generate-config)
│   └── mrpickles/hardware-configuration.nix
├── modules/
│   ├── flake-inputs.nix   # Flake input declarations — edit here, then run `nix run .#write-flake`
│   ├── hosts.nix          # Declares hosts and their attributes (monitors, isGaming, …)
│   ├── den.nix            # den framework setup, Home-Manager defaults, shared modules
│   ├── formatter.nix      # Wires treefmt.toml up as the flake's `nix fmt`
│   ├── nh.nix             # Exposes `nix run .#<host>` build apps via nh
│   ├── system/            # OS-level (boot, locale, networking, systemd, packages, ananicy, users)
│   ├── hardware/          # Hardware (bluetooth, coolercontrol, kernel, openrgb, udev, usb)
│   ├── nix/               # Nix itself (settings, overlays)
│   ├── security/          # Security (sops, pcscd, noctalia-greeter, polkit, gnome-keyring)
│   ├── desktop/           # Desktop (stylix, noctalia, gtk, xdg, nautilus, fonts, zen-browser, …)
│   │   └── hypr/          # Hyprland sub-aspect (hyprland.nix)
│   ├── shell/             # Shell + CLI tools (fish, helix, kitty, yazi, starship, opencode, …)
│   ├── media/             # Media (mpv, cava, pipewire, easyeffects, pics)
│   ├── gaming/            # Gaming (steam, mangohud, winboat) — gated on host.isGaming
│   ├── communication/     # Communication (vesktop)
│   ├── ide/               # Editors (zed)
│   ├── home/              # Home-Manager basics (common, files, packages)
│   ├── hosts/             # Host aspect definitions (one directory per host)
│   │   └── mrpickles/default.nix
│   └── users/
│       └── mrpickles/mrpickles.nix  # User aspect — all desktop/shell/app includes
├── assets/                # Wallpapers, logos, scripts, scopebuddy + AI agent configs
├── screenshots/           # Desktop screenshots for the README
└── secrets/               # SOPS age-encrypted secrets
```

> **Naming note:** the host is called `nixos-btw`, but its aspect lives in `modules/hosts/mrpickles/` and its hardware config in `hosts/mrpickles/` — both named after the user rather than the host. Worth knowing before you go looking for `hosts/nixos-btw/`.

| Host | Hardware | Role | Key Attributes |
| ------------- | ------------------------------------------------------- | ------- | -------------------------------------------------------------------- |
| **nixos-btw** | AMD Ryzen 7 7800X3D, NVIDIA RTX 3090, dual 165 Hz displays | Desktop | `isGaming=true`, `isMultiMonitor=true`, `nvidia_cachyos` (open kernel module), systemd-boot |

## Key Features

- **den Framework** — auto-generates `nixosConfigurations`, wires Home-Manager, provides `host`/`user` context
- **import-tree** — all `.nix` files under `modules/` are auto-discovered; no manual wiring needed
- **Aspect Pattern** — every feature is a self-contained file with optional `nixos` and `homeManager` sections
- **CachyOS Kernel** — `linuxPackages_cachyos-lto-znver4` via [chaotic-nyx](https://github.com/chaotic-cx/nyx), Zen4-optimized, with `INTEL_TDX_HOST` patched out of the prebuilt configfile
- **CachyOS NVIDIA driver** — `nvidia_cachyos`, patched for compatibility with the CachyOS kernel
- **Hyprland** — Wayland compositor with Lua config (hyprlang-lua), Stylix-driven border colors
- **Stylix** — system-wide theming with the palette derived from the wallpaper, Inter (sans-serif), custom hyprcursor-format Bibata Modern Ice cursors (built from source, see `modules/nix/overlays.nix`), WhiteSur icons
- **Noctalia Shell** — C++ shell, launcher, wallpaper management, and the greeter
- **Fish shell** — ported from zsh, with fastfetch on every new interactive terminal
- **Nautilus** — GNOME Files as the default file manager, with `nautilus-open-any-terminal` for right-click "Open Terminal Here"
- **Zen Browser** — via the [zen-browser-flake](https://github.com/youwen5/zen-browser-flake), set as default browser
- **ddcci backlight** — DDC/CI monitors exposed as `/sys/class/backlight`, manually bound because autoprobing broke on kernel 6.8+
- **ananicy-cpp** — automatic process scheduling priority, using CachyOS's rule set
- **Steam** — `proton-ge-bin` plus a CachyOS-optimized Proton build as selectable compatibility tools; session vars tuned for NVIDIA — NVAPI forced on, DXR via VKD3D-Proton, HDR, and DLSS/XeSS DLL upgrades (DLSS upgrade only honored under proton-cachyos)
- **SOPS** — age-encrypted secrets, decrypted to `/run/secrets/` at boot via systemd service
- **Conditional Includes** — aspects gated by `host.isGaming or false` via `lib.optionals`

## Usage

```bash
# Rebuild the system
sudo nixos-rebuild switch --flake .#nixos-btw

# Build without switching — the full check, compiles everything
nixos-rebuild build --flake .#nixos-btw

# Add or change a flake input: edit modules/flake-inputs.nix, then regenerate flake.nix
nix run .#write-flake
nix flake update <input-name>

# Update all flake inputs
nix flake update

# Format all .nix files
nix fmt
```

## Checks

CI runs on every push and PR ([`.github/workflows/check.yml`](.github/workflows/check.yml)):

| Check | Command | Catches |
| ----- | ------- | ------- |
| Config evaluates | `nix eval .#nixosConfigurations.nixos-btw.config.system.build.toplevel.drvPath` | Undefined options, type mismatches, bad interpolation, missing files |
| `flake.nix` in sync | `nix build .#checks.x86_64-linux.check-flake-file` | Editing `modules/flake-inputs.nix` without re-running `nix run .#write-flake` |
| Formatting | `nix fmt && git diff --exit-code` | Unformatted Nix |

All three run locally too — the eval is the one worth running before a rebuild, since it catches essentially every config error in under a minute.

**CI evaluates rather than builds, deliberately.** The CachyOS kernel and Proton packages are CPU-microarchitecture-specific (`-znver4`) and aren't in any binary cache, so a real build compiles a kernel from source — far past what a hosted runner can do. Evaluation resolves every module and option without compiling, which is where config errors actually live. Use `nixos-rebuild build --flake .#nixos-btw` locally for the genuine article.

## Den Framework Pattern

Each feature is a self-contained **aspect** file. NixOS and Home-Manager config for the same program live together:

```nix
# modules/hardware/example.nix
{ den, ... }:
{
  den.aspects.example = {
    nixos = { pkgs, ... }: {
      services.example.enable = true;
    };

    homeManager = { ... }: {
      # user-level config if needed
    };
  };
}
```

To access **host or user context**, use the outer aspect lambda:

```nix
{ den, lib, ... }:
{
  den.aspects.example =
    { host, user, ... }:
    {
      nixos = { pkgs, lib, ... }: {
        # host.hostName, host.isGaming or false, host.isMultiMonitor or false
        # Note: networking.hostName is set automatically by den._.hostname
      };

      homeManager = { osConfig, ... }: {
        # user.userName, user.gitName, user.gitEmail
        home.file."example".text = "hello ${user.userName}";
      };
    };
}
```

> **Note:** `host` and `user` are only available in the **outer** aspect lambda, not inside `nixos`/`homeManager` module args. Capture them via Nix's lexical scoping (they are automatically in scope for inner lambdas).
>
> **Note:** Host attributes are freeform — use `host.isLaptop or false` when an attribute may not exist on all hosts. A typo in a freeform attribute is silently falsy, not an error, so a gated aspect that never activates is usually a misspelled attribute name.

For **conditional includes** with `lib.optionals`:

```nix
{ den, lib, ... }:
{
  den.aspects.example =
    { host, ... }:
    {
      includes = [
        den.aspects.steam
      ]
      ++ lib.optionals (host.isGaming or false) [
        den.aspects.mangohud
      ];
    };
}
```

## Adding a New Aspect

1. Create `modules/<category>/my-feature.nix` — import-tree picks it up automatically.
2. Add `den.aspects.my-feature` to the user's includes in `modules/users/mrpickles/mrpickles.nix` (for user-facing features) or to the host's includes in `modules/hosts/mrpickles/default.nix` (for system-only features).
3. Rebuild.

> Defining an aspect is not enough to activate it — an aspect that is never added to an `includes` list is simply inert. If a new feature seems to do nothing, check that first.

```nix
# modules/category/my-feature.nix
{ den, ... }:
{
  den.aspects.my-feature = {
    nixos = { pkgs, ... }: {
      services.myservice.enable = true;
    };

    homeManager = { pkgs, ... }: {
      programs.myservice.enable = true;
    };
  };
}
```

## Adding a New Host

1. Add the host to `modules/hosts.nix`:

```nix
den.hosts.x86_64-linux = {
  mynewhost = {
    users.mrpickles = mrpickles; # reuse the user attrset defined in the let block

    # Optional — add any freeform attributes your aspects need:
    # isGaming = true;
    # isLaptop = false;
    # timezone = "America/New_York";
  };
};
```

2. Create `modules/hosts/mynewhost/default.nix`:

```nix
{ den, inputs, ... }:
{
  den.aspects.mynewhost = {
    includes = [
      # Core system
      den.aspects.boot
      den.aspects.locale
      den.aspects.networking
      den.aspects.systemd
      den.aspects.users
      den.aspects.overlays
      den.aspects.nixsettings

      # Hardware
      den.aspects.bluetooth
      den.aspects.kernel
      den.aspects.usb

      # Security
      den.aspects.sops
      den.aspects.pcscd
      den.aspects.noctalia-greeter
      den.aspects.polkit

      # System packages
      den.aspects.systempackages
    ];

    nixos = { lib, ... }: {
      imports = [ (inputs.self + "/hosts/mynewhost/hardware-configuration.nix") ];
      # hostname is set automatically from den._.hostname (host name = "mynewhost")
      # boot, hardware, networking specifics...
    };
  };
}
```

3. Add `hosts/mynewhost/hardware-configuration.nix` (from `nixos-generate-config`).

That's it — den auto-generates the `nixosConfiguration` output from `hosts.nix`.

## Adding a New User

1. Create `modules/users/<username>/<username>.nix`:

```nix
{ den, lib, ... }:
{
  den.aspects.<username> =
    { ... }:
    {
      includes = [
        den.aspects.fish
        den.aspects.git
        # ... all aspects this user should have, look at mrpickles for full list
      ];

      nixos = { ... }: {
        # den._.define-user, den._.primary-user, and den._.user-shell handle
        # isNormalUser, shell, and wheel automatically — only add extras here
        users.users.<username> = {
          extraGroups = [ "audio" "video" "networkmanager" ];
        };
      };
    };
}
```

2. Add the user to the host entry in `modules/hosts.nix`:

```nix
mynewhost = {
  users.myuser = {
    gitName = "My Name";
    gitEmail = "me@example.com";
  };
};
```

## Notes to self

- Flakes only see git-tracked content — a dirty-but-unstaged file is invisible to Nix even though it's sitting right there on disk. `git add` before every rebuild.
- Some Chaotic-Nyx packages (CPU-microarchitecture-specific builds like `-znver4`/`_x86_64_v3` variants) aren't covered by their binary cache and compile locally — and can occasionally hit upstream hash-mismatch issues if their mirror serves updated content at a pinned filename. If a rebuild fails with a fixed-output hash mismatch on one of these, that's the likely cause, not a config error. `nix flake update chaotic` often resolves it once their bot catches up.
- `systemd.services.<name>.serviceConfig` keys are **not** validated by NixOS — a typo like `StanardOutput` is written straight into the unit file, where systemd discards it as an unknown directive and carries on silently. If a unit setting seems to have no effect, check the spelling against the generated unit: `nix eval .#nixosConfigurations.nixos-btw.config.systemd.units.\"<name>.service\".text`.
- `mkOutOfStoreSymlink` does not check that its target exists, by design. Pointing one at a path that isn't there produces a dangling symlink with no error at build or switch time.
